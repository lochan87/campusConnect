# 05 — Data Models

All data is stored in **Cloud Firestore**. There is no SQL database.
Unless noted, all timestamps are Firestore `Timestamp` objects that are converted to JavaScript `Date` or ISO strings in responses.

---

## Collection: `users`

Document ID: auto-generated by Firestore (used as `uid` throughout).

| Field | Type | Notes |
|-------|------|-------|
| `email` | string | Unique; checked before write |
| `password` | string | bcrypt hash |
| `displayName` | string | `${firstName} ${lastName}` |
| `firstName` | string | |
| `lastName` | string | |
| `studentId` | string | |
| `campusId` | string | Links all user content to a campus scope |
| `department` | string | Full department name |
| `departmentSlug` | string | Auto-generated: first word, lower, underscores |
| `year` | string | e.g. `"2nd Year"` |
| `bio` | string | Optional |
| `avatar` | string | base64 data URL (stored inline in Firestore) |
| `role` | string | `"student"` \| `"admin"` \| `"moderator"` |
| `isActive` | boolean | |
| `isVerified` | boolean | Set to `true` at registration in practice |
| `reputation` | number | Starts at 0; never decreases |
| `postCount` | number | Incremented on post/poll/event creation |
| `pollCount` | number | Incremented on poll creation |
| `eventCount` | number | Incremented on event creation |
| `joinedAt` | Timestamp | Set at registration |
| `lastActive` | Timestamp | Updated on post creation, rep changes |
| `preferences.notifications` | object | `{ posts, polls, events, memes }` booleans |
| `preferences.privacy` | object | `{ showProfile, allowDirectMessages }` booleans |

**Known inconsistency:** The frontend's `demoLogin()` generates mock users that are never written to Firestore. They exist only in localStorage. The backend endpoints that accept a `userId` (like posts, polls) will successfully reference a non-existent user document — the Firestore write succeeds, but no user document exists. This is an expected side-effect of the demo mode.

## Collection Relationships

```
users
  ├── posts          (posts.userId = users.docId)
  │   ├── comment_post  (comment_post.postId = posts.docId)
  │   ├── like_post     (like_post.postId = posts.docId)
  │   └── post_reports  (post_reports.postId = posts.docId)
  │
  ├── polls          (polls.userId = users.docId)
  │
  ├── events         (events.userId = users.docId)
  │   ├── comment_event (comment_event.eventId = events.docId)
  │   └── like_event    (like_event.eventId = events.docId)
  │
  └── conversations  (conversations.participants[] = users.docId)
      └── messages   (sub-collection)
```

**No foreign key enforcement** — Firestore does not support referential integrity. Cascading deletes are handled manually in Firestore transactions within each DELETE route handler.

## What's NOT Stored in Firestore

| Item | Where it lives |
|------|---------------|
| JWT tokens | Client `localStorage` only |
| Session state | Client `localStorage` only |
| In-app notifications | Client `localStorage` (keyed by uid) |
| Demo user accounts | Client `localStorage` only — never in Firestore |
| Poll voter arrays (in responses) | Stripped before sending; only in Firestore |
